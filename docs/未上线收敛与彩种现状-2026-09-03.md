# 未上线项目收敛与彩种现状（2026-09-03）

本文描述当前代码合同，不代表所有彩种已经开放，也不是上线或经营配置记录。此前按日期保存的审计文档保留原始证据；其中旧版本、默认赔率和开放状态以本文及当前代码为准。

## 单一入口与边界

- 数据库结构只来自 `backend/migrations/*.sql`。启动不再执行 `AutoMigrate`、无版本补表、反复删除/重建索引或自动合并重复业务记录。
- 新库完整执行核心基线与后续迁移；已有版本库按校验和增量执行。无版本但已有表、视图或序列的库，以及缺少核心基线的旧账本，明确拒绝接管。
- 保留 SQL 迁移历史及校验和，不将已有数据库“自动清零”。需要重建开发库时走有备份、sentinel 和明确确认口令的本地重置工具。
- 规则绑定由 `backend/services/game_rules.go` 管理；玩法目录只描述玩法，不附带代码默认赔率。下注、结算、前端选项及说明必须使用同一游戏身份。
- 已受理票据的赔率、规则版本、金额、幂等键和账务凭证继续保留。删除的是空版本猜测、`digits5-v2`、`mark6-v1` 的运行时结算分支，不是票据证据。缺少或不匹配的规则快照停止结算，不自动改写。
- 自动生成开奖号码只允许明确配置的 `platform` / `simulated` 来源；来源为空不能再被当作平台自开。

## 赔率配置

1. 平台先按当前彩种和规则版本明确保存赔率；有效配置必须具备 `admin_save` 来源。缺失、旧合同或未确认的配置不生效。
2. 房间、会员覆盖只能覆盖已经有效配置的平台玩法，不能重新打开未配置/已关闭玩法。重新打开的玩法不继承先前残留覆盖。
3. 平台保存、清空操作携带规则版本与配置修订标识；游戏行锁和单调递增的修订号防止并发覆盖，也防止“清空再恢复”绕过冲突检测。
4. 读取配置不补价格、不写数据库。不存在恢复代码默认赔率的入口；原版文档中的账号赔率仅作原文参考。
5. 金额、有效赔率、规则版本仍在受理时保存快照；后台改价不会重新定价已受理注单。旧版/未知合同票据需明确处理，不猜测结算。
6. 单注最高、会员单期、全房单期限额填写 `0` 时保留“不限额”含义，不再被模型默认值覆盖；开启玩法的单注最低仍必须大于零。
7. 会员交易设置只更新飞单、返水等明确字段，不整行回写余额、密码、认证版本或账户状态。投注、会员/房间赔率修改及计划访问统一先锁游戏，再获取各自所需的账户、房间或配置锁。

管理端支持按玩法分类筛选、批量设置和未保存提示；保存冲突时保留草稿，要求读取最新配置后重新编辑。分类显示跟随已接受的彩种，取消切换或保存期间拒绝切换时不会让分类与报价表错位。会员交易弹窗按会员、彩种和请求代次隔离读写，加载时禁止编辑/保存；关闭重开、乱序或迟到响应不能回填其他会员或覆盖新草稿。

边界：本轮取消的是普通玩法的代码默认报价，不改动已实现的 PC28 版本条件规则。PC28 在13/14下的固定降赔、通吃、退本及有效流水属于现有结算合同；不能把它们误当作缺价兜底，也不能无版本变更地替换。
