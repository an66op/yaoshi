## 当前生产合同

- 163 ID185 是保留真实开出顺序的20球母源，ID135只核对同期期号、开奖时间和20球集合；任一侧缺失、越界、重复或不一致时，不生成可结算的宾果六合彩结果。
- 从核对通过的ID185原序依次筛选01–49，取最先符合的7个；前6个为正码、第7个为特码，50–80跳过，整期不足7个合格号码则视为异常。
- `bingo-mark-six`固定使用`mark6-v2`，已覆盖原版全部详细网投市场；聊天投注仍明确关闭。
- 本次已依据用户提供的原版资料与参考盘，通过后台配置服务显式补齐当前运营赔率。页面出现玩法仍不等于无条件开放：普通公开玩法使用自身定价行，组合父玩法使用本注所需的全部后台内部定价行；每个必要行都必须同时具有有效赔率、单注最低、单注最高、会员单期与全房单期限额。任何必要项缺失即关闭，运行时不采用前端默认赔率或跨彩种借价。

## 完整玩法与定价模型（2026-09-04）

当前服务端注册以 [`mark_six_rules.go`](../../backend/services/mark_six_rules.go) 为准。原版详细网投市场已经全部纳入`mark6-v2`，不再存在“有入口但模型未实现”的宾果六合彩玩法。

| 项目 | 当前合同 |
| --- | --- |
| 一尾 | 0–9尾逐项定价；全部7个开奖号码中出现所选尾数即中，同尾重复出现仍只派一次。 |
| 合肖 | 2–11肖按选择数量分别使用公开玩法与独立报价；特码命中所选任一生肖即中，特码49和局返本。 |
| 正肖 | 12生肖逐项定价，只统计前6个正码；命中几球就将冻结赔率的净赢部分放大几份，本金只返还一次。 |
| 连肖、连尾 | 2–5连使用公开父玩法提交一张组合票；服务端从全部所选生肖／尾数的后台内部定价行取最低有效赔率，49正常参与。组件定价行不能由会员独立下注。 |
| 三中二、二中特 | 两者都是一张票、一次扣款。三中二同时冻结“中二／中三”两档，二中特同时冻结“中特／中二”两档；结算按互斥结果选择对应快照，不重新读取实时赔率。 |
| 自选不中 | 5–11不中按选择数量分别注册与定价；所选号码全部避开当期7球才中奖。 |
| 既有市场 | 特肖、一肖、总肖、七色波、特码／正码、两面、头尾、五行、半波／半半波及其他连码继续使用各自原子价或公开玩法价。 |

连肖、连尾、三中二及二中特采用“公开投注码＋后台内部定价码”分层：会员只提交公开父玩法；管理端可查看、配置组件或档位定价行。内部定价行会参与赔率、单注最低、单注最高、会员单期与全房单期的完整校验，但直接提交会被服务端拒绝。组合玩法对本注所需的全部定价行执行严格校验，不允许只配置其中一部分后退回通用赔率。

结算与价格追踪：[`mark_six_rules.go`](../../backend/services/mark_six_rules.go)、[`settlement.go`](../../backend/services/settlement.go)、[`odds_pricing.go`](../../backend/services/odds_pricing.go)、[`trading_admin.go`](../../backend/services/trading_admin.go)。普通玩法使用注单冻结赔率；三中二、二中特额外冻结版本化双档赔率条款；连肖、连尾冻结实际采用的最低组件定价码；正肖只使用下注时赔率并按命中数计算有效派彩。
