# 生产验收测试

这套测试只面向一次性的本机或 CI 环境，验证正式模式能从空数据库完成迁移和首位管理员引导，并连通真实 PostgreSQL、Redis、两套前端与 WebSocket。它不会使用 SQLite、内存数据库或模拟 Redis。

## 覆盖范围

- 在名称以 `wangzhe_ci_` 开头的一次性 PostgreSQL 数据库上执行全部版本化迁移。
- 通过 `bootstrap-admin` 的 0600 密码文件创建唯一首位管理员，并确认第二次引导被拒绝。
- 确认 release 模式不生成本地体验账号，后端能通过 `/health`、`/ready`，重启后仍可用。
- 检查 Redis 版本至少为 6.2，要求独立的应用/监控 ACL 凭据和 `appendonly=yes`；监控用户通过只读 `ACL LIST/GETUSER` 验证应用用户仅有预期键、频道和命令权限，release readiness 因此真实依赖 Redis。
- 检查公开管理注册 `POST /api/register` 在 release 下严格返回 404、匿名会话返回 401、登录使用带 `Secure`、`HttpOnly`、`SameSite=Lax` 的 Cookie。
- 通过真实管理 API建立一次性代理、房间和会员，覆盖普通登录及 50 字符账号、72 字节密码边界。
- 在真实 PostgreSQL 上并发启用两个机器人工作区，验证 advisory lock 使一个成功、一个因上限失败，且失败事务完整回滚；测试不创建机器人账号，因此不会生成注单。
- 以自签名 HTTPS 边缘代理运行 Chromium E2E，覆盖管理员登录、会员管理、飞单管理、监控页、会员登录、进房和主菜单切换。
- 执行受限的 HTTP/WebSocket 烟测，包括健康/就绪、会员资料、聊天读取及少量聊天写入；不产生下注或资金变更。

## 本地运行

需要 Go、Node.js 24、PostgreSQL 客户端、Redis 客户端、OpenSSL，以及本机正在运行的 PostgreSQL 和 Redis。测试数据库账号必须拥有创建和删除一次性数据库的权限；不要使用正式数据库账号。请使用隔离的测试 Redis，为应用与监控分配两套不同的 ACL 账号/密码，并启用 AOF。两个密码都必须至少 24 位：

```bash
redis-cli CONFIG SET appendonly yes
redis-cli CONFIG SET acl-pubsub-default resetchannels
redis-cli ACL SETUSER wangzhe-app reset on '>LocalRedisApp#2026_x9Q7mL2vR8s' \
  resetkeys '~wangzhe-system-test:*' resetchannels '&wangzhe-system-test:*' -@all \
  +ping +hello +select +get +set +getdel +del +incr +pexpire +pttl +eval +evalsha \
  +publish +subscribe +unsubscribe +xadd +xread +xtrim +xrevrange \
  +zadd +zrem +zremrangebyscore +zcard +time
redis-cli ACL SETUSER wangzhe-monitor reset on '>LocalRedisMonitor#2026_v8K4pN6sT1dF' \
  resetkeys resetchannels -@all +ping +info '+config|get' '+acl|whoami' '+acl|list' '+acl|getuser'
redis-cli ACL SETUSER default reset off
make production-test-install
SYSTEM_TEST_ALLOW_LOCAL=1 \
SYSTEM_TEST_POSTGRES_ADMIN_USER=wangzhe_ci_admin \
SYSTEM_TEST_POSTGRES_ADMIN_PASSWORD='LocalDatabaseAdmin#2026_x9Q7mL2' \
SYSTEM_TEST_POSTGRES_APP_PASSWORD='LocalDatabaseApp#2026_v8K4pN6sT1dF' \
SYSTEM_TEST_REDIS_USERNAME=wangzhe-app \
SYSTEM_TEST_REDIS_PASSWORD='LocalRedisApp#2026_x9Q7mL2vR8s' \
SYSTEM_TEST_REDIS_MONITOR_USERNAME=wangzhe-monitor \
SYSTEM_TEST_REDIS_MONITOR_PASSWORD='LocalRedisMonitor#2026_v8K4pN6sT1dF' \
make production-system-test
```

也可以分开执行：

```bash
export SYSTEM_TEST_ALLOW_LOCAL=1
export SYSTEM_TEST_POSTGRES_ADMIN_USER=wangzhe_ci_admin
export SYSTEM_TEST_POSTGRES_ADMIN_PASSWORD='LocalDatabaseAdmin#2026_x9Q7mL2'
export SYSTEM_TEST_POSTGRES_APP_PASSWORD='LocalDatabaseApp#2026_v8K4pN6sT1dF'
export SYSTEM_TEST_REDIS_USERNAME=wangzhe-app
export SYSTEM_TEST_REDIS_PASSWORD='LocalRedisApp#2026_x9Q7mL2vR8s'
export SYSTEM_TEST_REDIS_MONITOR_USERNAME=wangzhe-monitor
export SYSTEM_TEST_REDIS_MONITOR_PASSWORD='LocalRedisMonitor#2026_v8K4pN6sT1dF'
make integration-test
make e2e-test
make load-test
```

每次运行都会生成全新的数据库，并在退出时只删除本次创建、且通过 `wangzhe_ci_` 名称校验的明确数据库。脚本拒绝远程 PostgreSQL/Redis，防止误用正式环境。

## 负载烟测安全边界

默认目标为 `http://127.0.0.1:18080`，并要求 `SYSTEM_TEST_ALLOW_LOCAL=1`。单独调用 `tests/system/load-smoke.mjs` 访问非回环地址时，还必须同时满足：

```bash
LOAD_TEST_BASE_URL=https://staging.example.com \
LOAD_TEST_AUTHORIZED_ORIGIN=https://staging.example.com \
LOAD_TEST_CONFIRM=I_UNDERSTAND_THIS_GENERATES_TRAFFIC \
node tests/system/load-smoke.mjs
```

仅应对明确获准的隔离 staging 使用这一开关。默认门槛为错误率不超过 1%、p95 不超过 1500ms；可通过 `LOAD_MAX_ERROR_RATE`、`LOAD_MAX_P95_MS`、`LOAD_READ_REQUESTS`、`LOAD_WRITE_REQUESTS` 和 `LOAD_CONCURRENCY` 调整。公开生产环境不应运行写入烟测。

## CI

`.github/workflows/system-test.yml` 使用固定版本的 PostgreSQL 16.15 和 Redis 7.4.11 service containers。CI 先用管理账号创建无超级权限、无 `CREATEDB/CREATEROLE/REPLICATION/BYPASSRLS` 的一次性应用 owner，再由该角色执行迁移与运行时测试。CI 启用 Redis AOF/`everysec`/`noeviction`，用 `reset`/`-@all` 从零建立权限隔离的 `wangzhe-app`/`wangzhe-monitor` ACL 用户，真实执行只读 `ACL LIST/GETUSER`，并证明跨前缀键/频道、`CONFIG`、`ACL`、`FLUSHDB` 都返回 `NOPERM`；`default` 用户会同时 reset 和关闭。随后安装锁定的前端/Playwright 依赖，完成发布包门禁后再执行完整 fresh-release 测试。

浏览器失败产物保存在 `tests/e2e/test-results`，HTML 报告位于 `tests/e2e/playwright-report`；这些目录均为生成物，不应提交。CI 失败时会将它们作为保留 7 天的诊断 artifact 上传。
