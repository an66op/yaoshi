# 登录图片验证码

会员登录和管理后台登录均需要手动填写 6 位数字图片验证码。平台管理员、租户和代理共用管理后台入口；验证码不能跨前后台使用。开发/测试账号可以预填账号密码，但没有验证码预填、固定答案或免验证开关。

## 接口

| 入口 | 获取图片 | 提交登录 |
| --- | --- | --- |
| 管理后台 | `GET /api/login/captcha` | `POST /api/login` |
| 会员前台 | `GET /api/member/login/captcha` | `POST /api/member/login` |

获取接口沿用现有 JSON 响应封装，`data` 仅含 `id`、`image`、`expires_in`。`image` 为 PNG base64 data URL，`expires_in` 为 120 秒；响应禁止缓存，不返回答案。

登录请求增加两个必需字段：`captcha_id` 和 `captcha_code`，与 `username`、`password` 一起提交。身份与归属继续由账号决定，不能通过验证码或前端身份按钮指定。

## 校验与存储

- 后端先验证图片验证码，再查询账号并校验密码。
- 验证码绑定用途和服务端识别的客户端 IP，两分钟有效。合法挑战 ID 的验证尝试会消耗该挑战，答错、跨端使用、不同 IP 或重复使用均不能通过。
- Redis 使用带过期时间的摘要记录，`GETDEL` 原子消费；多实例之间也不能重复使用。
- 只有未配置 Redis 的 debug/test 单实例允许使用有容量上限的短期内存存储。release 或已配置 Redis 但连接故障时拒绝验证，不降级放行。
- 刷新图片有独立的每 IP 每分钟 20 次限流；原有每 IP 每分钟 10 次登录限流保留。
- 缺失、错误、过期验证码返回 400，超频返回 429，验证码服务不可用返回 503。

反向代理必须正确配置受信任代理和 Origin 白名单。更换网络/IP 后需刷新图片再登录。验证码增加基础防护，不能替代强密码、权限隔离和登录限流。

## 页面行为

点击图片可以换一张。图片加载完成前不能提交；获取请求 15 秒超时可手动重试，验证码两分钟过期后需换图。登录失败保留账号密码，清空验证码并请求新图片；不自动重复登录。

## 自动化验证

后端单元测试覆盖一次性消费、过期、用途/IP 隔离、并发重放和 Redis 故障关闭；前端生命周期测试覆盖输入、换图、图片解码失败、超时、过期和重复提交。

fresh-DB 系统测试使用测试目录内的 Redis fixture helper，仅允许本机后端、本机 Redis 和 `wangzhe-system-test:<runid>` 隔离前缀。它为测试写入已知答案的一次性摘要，不给生产二进制添加任何绕过接口，也不识别真实验证码。浏览器测试替换挑战 ID 以使用该 fixture，登录 POST 仍走真实验证。

负载测试复用预先认证的、权限为 0600 的会话文件，不在压测期间自动破解或绕过验证码。会话文件绑定精确目标 origin，不可发送到其他站点。

旧 `scripts/local-smoke.sh` 仍依赖已废弃的 bearer-token 登录方式，不适用于当前 cookie/验证码认证；使用 `scripts/release-system-test.sh` 的隔离验收流程。
