# 前端本地数据与清理边界

本文盘点用户端 `new` 与管理端 `new-back` 在浏览器保存的数据，以及数据库重置后可能出现的旧数据或初始化依赖。浏览器清理与数据库删除是两套机制；本文没有执行任何删除操作。

## 用户端 `new`

### 业务会话数据（退出或鉴权失效时清理）

| 键 | 内容 | 数据库重置风险 | 当前处理 |
| --- | --- | --- | --- |
| `yaotu-member-token` | 会员令牌 | 指向已删除账号 | 401、鉴权失效和主动退出时清理 |
| `seven-star-session` | 账号、昵称、房间、余额快照 | 会显示旧余额、旧房间 | 鉴权失效和主动退出时清理；启动验证失败时阻止展示旧快照 |
| `seven-star-room-history` | 按账号记录的最近房间 | 可能引用已删除房间 | 鉴权失效和主动退出时清理 |
| `seven-star-demo-state` 中的 `checkedIn`、`chatUnread` | 派生状态 | 可能保留旧签到/未读数 | 清零，但保留同一键中的主题 |
| `wangzhe-login-announcements-shown:*`（sessionStorage） | 本次标签页已展示公告标记 | 新库公告可能不再弹出 | 登录、退出和鉴权失效时清理 |

清理函数位于 `new/src/utils/businessStorage.ts`。它只清理后端业务绑定数据，不提供“一键清空整个 localStorage”的危险操作。

### 个人偏好（明确保留）

- `seven-star-demo-state.theme`：日间/夜间主题。
- `seven-star-font-scale`：字体大小。
- `seven-star-avatar`：本机头像选择。
- `seven-star-notification-muted`、`seven-star-notification-sounds`：静音及声音选择。
- `seven-star-draw-history`：开奖列表显示条数。
- `seven-star-bet-mode`：默认投注面板。

上述键与数据库业务记录无关，数据库重置、退出登录或鉴权过期均不清除。

### 初始化依赖与真实空态

- 开发环境登录框会填充 `wangzhe88 / Wz888888`；管理端开发登录框会填充平台、租户、代理三组本地账号。这些是开发便利，不是浏览器缓存；数据库重置后若未重建账号，登录会由接口明确失败。
- 注册和房间入口默认填充房间号 `8801`。这是入口默认值，不代表房间一定存在，最终必须由后端校验。
- 彩票接口缺少开奖号码时现在返回空号码，不再补成五个 `0`。
- 计划群列表不再写死“3 个彩票”；计划列表与详情只读取房间后端数据。
- 签到页不再写死 5/8/12/18/25/35/50 奖励，天数读取活动配置，具体奖励以签到接口到账结果为准。
- 活动、通知、聊天、注单、钱包和计划没有 localStorage 业务回退；接口失败显示错误或空态。

## 管理端 `new-back`

| 键 | 内容 | 当前处理 |
| --- | --- | --- |
| `yaotu-admin-token` | 管理登录令牌 | 401、主动退出或会话不完整时清理 |
| `yaotu-admin-user` | 当前管理身份快照 | 与令牌必须成对且结构有效，否则两者一起清理 |
| `yaotu-back-theme` | 后台主题 | 始终保留 |

管理端没有将报表、用户、注单、聊天、机器人或申请列表写入 localStorage/sessionStorage。开发环境的三种身份预填账号来自 `LoginPage.tsx`，不是持久化业务数据。

## 浏览器缓存能力

两个前端均未注册 Service Worker，未使用 Cache Storage、IndexedDB 或 Workbox。因此数据库重置后不会从这些离线缓存恢复业务记录。`dist` 目录只是构建产物，不是运行时业务缓存。

## 安全清理原则

1. 后端 401 是强失效信号：清理当前身份、房间历史、派生未读状态和标签页公告标记。
2. 后端短时不可用时不显示 localStorage 中的旧余额和旧房间；页面进入“重新读取账号”状态。
3. 主动退出清理该账号的业务会话，避免共享设备看到前一账号房间历史。
4. 不使用 `localStorage.clear()`，避免误删主题、字体、头像和声音偏好。
5. 数据库正式清理仍由后台数据维护策略和审计流程完成，前端清理不能替代数据库删除。
