# 规则核对后的本地安全优化

> 历史快照：本文保留当时的审计记录；当前规则版本、赔率与开放边界见[2026-09-03 收敛记录](未上线收敛与彩种现状-2026-09-03.md)。

日期：2026-09-01。对应用户“先优化吧”，仅修复上一轮已确认的本地问题，不把不同网站的条款拼成一套新玩法。

本轮没有改写业务库中的赔率、余额、开奖结果或历史注单，没有新增迁移，没有 Git 提交、服务器部署或重启业务后端。前端修改可由本地开发服务热更新；后端修改仍需重新启动本地服务才生效。

## 1. 下注生命周期：每次提交保存独立合同

- 没有外部请求标识的内部提交，生成新的随机请求引用；同一次财务操作的流水与注单使用相同引用。
- 不再查询旧注单并覆盖金额、赔率或状态。追加下注不会重定价前一单；取消后再次下注不会落入已取消单。
- 同一批输入的相同选项只在本批内合并，赔率、返点和分润快照必须相同；不同批次永不合并。
- 既有会员幂等入口保留：同一请求重试返回既有结果，不二次扣款。扣款、流水、新注单同事务，任一步失败整体回滚。
- 统计笔数可能增加，这是每次提交独立保存的预期变化；不改变投注总额和应退金额。例如两次直接下注各2元，再一条助手下注2元，取消结果应为3笔、退款6元，重试不增单。

实现：[bet_admin.go](../backend/services/bet_admin.go)。回归：[纯测试](../backend/services/bet_placement_lifecycle_test.go)、[PostgreSQL生命周期测试](../backend/services/bet_placement_lifecycle_postgres_test.go)。

## 2. 宾果原始号码：先校验，再转换

168台湾宾果 `lotCode=10047` 必须返回恰好20个互异的1–80整数。允许正常首尾空格和前导零；拒绝空项、损坏字符串、正负号、小数、溢出、重复、越界、多球和少球。

最新、今日历史、昨日历史任一响应存在坏记录，整次宾果抓取失败；重复期号中的坏记录也不能被去重掩盖。校验覆盖全部原始记录，之后才进入七个衍生彩转换，因此坏原球不能被赛车补齐逻辑伪装成合法开奖。

合法原球的既有公式、顺序、期号及输出不变，非宾果来源保持兼容；历史接口纯网络故障的原有容错不改。未替换宾果四路时时彩、赛车A/B、六合彩的转换公式，也未宣称这些公式与外站同名产品一致。

实现：[lottery_sources_168.go](../backend/services/lottery_sources_168.go)。回归：[宾果源校验](../backend/services/lottery_sources_168_bingo_validation_test.go)。

## 3. 前后端解析与数字彩详细板

会员端预解析与当前后端保持一致，覆盖总和、总和尾、前三形态、第N球、赛车第十名简写以及单项金额展开。未知彩种、非法玩法或损坏格式整条拒绝，不再默认为第一球号码玩法。

| 输入 | 修复后的含义 |
| --- | --- |
| `总和单/100` | 总和单，1项100 |
| `总和尾7/100` | 总和尾7，1项100 |
| `总和/大小单双/20` | 总和4项，各20，共80 |
| `前三豹子/50` | 前三豹子，1项50 |

数字彩详细板补齐已有的龙虎入口：五球1对5、2对4，三球1对3；选项独立，读取 `dragon_tiger` 实际赔率。没有增加“和”投注，没有改判奖或退款逻辑。切换游戏清空旧选择，未取得有效赔率不得提交。

## 4. 赔率风险：提示与新投注保护，不替换数值

只对已证明五种前三形态互斥且穷尽的 `digits3-v2`、`digits5-v2` 合同检查。算法使用与实际赔率相同的四位小数精度，并用精确有理数判断五种含本金赔率的倒数和；小于1代表存在完整覆盖获利组合。等于1不会因浮点误差被拒绝。

- 平台赔率页面读取、保存、恢复默认后显示已保存配置的风险提示，不静默修改任何赔率。
- 新形态下注按实际账户价格检查：会员专属赔率优先，其次房间赔率×会员倍率，再次平台赔率×会员倍率。倍率和三层赔率通过一条SQL在同一数据库快照读取。
- 选中项使用本次已取得的实际报价，不能用后来读取的另一价格替代。
- 批次全部报价完成后，在扣款前再核对本批实际形态报价；同一形态取最高价作保守检查，避免安全配置A、B之间改价拼出危险批次。
- 有风险返回 `ODDS_RISK_UNSAFE`，整单不扣款、不创建注单；普通号码、其他玩法不因此被关闭。非形态下注不会增加风险查询。
- 已受理的旧单继续按保存赔率和规则结算，不套用新下注风控，更不会重定价或删除。

并发改价回归使用两套各自安全的测试配置：A为50/2/2/2/2，B为1.2/20/20/20/20。首项取A、其余取B会形成50/20/20/20/20的危险组合；测试确认逐行检查均完成，最终批次检查拒绝，余额和流水不变。这个测试在隔离事务内确定性插入配置变化，不声称完成真实多连接压力测试。

边界：这不是全站敞口系统。没有审计所有房间和会员的存量配置，也不覆盖跨会员、跨请求、历史已受理价格组合、返点、分润或飞单造成的全部风险。测试中的安全赔率仅为夹具，不是建议采用的业务价格。未来v3合同不能自动继承当前互斥假设。

实现：[odds_risk.go](../backend/services/odds_risk.go)、[trading_admin.go](../backend/services/trading_admin.go)、[odds_admin.go](../backend/services/odds_admin.go)、[LimitsPage.tsx](../new-back/src/pages/LimitsPage.tsx)。回归：[数学边界](../backend/services/odds_risk_test.go)、[真实数据库回归](../backend/services/odds_risk_postgres_test.go)。
